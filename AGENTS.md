# AGENTS.md

Instructions for AI coding agents (Claude Code, Codex, Cursor, Copilot…) and humans working in this repo. [README.md](README.md) has the full picture: status, tech stack, how the market works, and **What's not done**. Read the status table and the section you're touching before you change anything.

## What this is

Promptflix: a marketplace for AI filmmakers. Static site on GitHub Pages, no build step. The marketplace is in `market/`. It is a working prototype: data lives in the browser (`localStorage` + IndexedDB) and payments and sign-in run in demo mode until keys are set in `market/config.js`.

## Hard rules

1. **No build tools, frameworks or npm dependencies.** Plain HTML/CSS/JS, served as committed. Don't add a bundler, TypeScript for the front end, React, Tailwind, or a `package.json` unless the team asks.
2. **Never commit secrets.** `market/config.js` is public: only publishable keys (`pk_…`, Supabase publishable key, Google client ID, PayPal client ID). Stripe secret keys, webhook secrets, PayPal secrets, the Google client secret and the Supabase service-role key go in Supabase function env or the provider dashboards. `scripts/check.mjs` fails the PR if one slips in.
3. **Merging to `main` deploys to production immediately.** `main` is protected: work on a branch, open a PR, pass the `check` workflow, get one approval. Never push to `main`.
4. **Run `node scripts/check.mjs` before you push.** CI runs the same thing.
5. **Pin third-party script versions** that support pinning (e.g. `supabase-js@2.117.3`). Don't bump them silently.
6. **Don't edit `market/creators.js` by hand.** It's generated by `market/tools/gen.py`.
7. **Be honest in the product.** Unclaimed creators show estimates marked `~`, never invented prices, ratings or quotes. Never fake Google's (or any provider's) sign-in or checkout UI; use their real SDKs.
8. **Never commit `.DS_Store`** or absolute local paths. Use relative paths for media.
9. **Leave the root `index.html` Supabase edits alone** unless asked; the feed app is offline until its schema is run on a new project.

## How the code fits together (the traps)

- **One global scope.** Each page loads classic `<script>`s in a fixed order: `seed.js → creators.js → config.js → store.js → ui.js → auth.js → pay.js → voice.js → <site>.js`. A top-level `const`/`let`/`function` name used in two files breaks the whole page with "Identifier has already been declared". Pick distinctive names. The check script catches this.
- **`APP` is defined last**, in the site script (`merchant.js`, `creator.js`, `admin.js`). Shared files must not read `APP` at load time, only inside functions that run later.
- **Top-level `const` is not on `window`.** Use `typeof Auth !== "undefined"`, not `window.Auth`.
- **Referrer policy.** Every page has `<meta name="referrer" content="no-referrer">` because X's video CDN rejects cross-site referrers. `auth.js` switches it to `strict-origin-when-cross-origin` while the sign-in sheet is open (Google needs the origin) and `closeSheet()` restores it. Don't remove either half.
- **Data layer.** All reads and writes go through `DB` in `store.js` and end in `DB.save()`, which fires `pfm:change` and re-renders. Every `DB` method will become one Supabase table call or RPC; keep names and record shapes stable. If you change a stored shape, migrate old records in `DB.load()` or bump `KEY`.
- **Order states.** `negotiating → agreed → in_production → trial_review → revising → final_due → completed`, or `cancelled`. Escrow moves only inside `store.js` (`payDeposit`, `decide`, `payBalance`, `breakContract`). Commission is `COMMISSION` (10%).
- **Live vs demo.** `LIVE.auth / google / stripe / paypal` in `config.js` decide each path. Every new integration needs a demo path that runs with empty keys.
- **Local server caches.** `python3 -m http.server` lets the browser keep old scripts. Hard-reload before you trust a test.

## Verifying a change

- `node scripts/check.mjs` must pass.
- For any UI change: `python3 -m http.server 8131`, open `http://localhost:8131/market/` (and `/creator/`, `/admin/` if shared code changed), click through the flow you touched, check the console for errors, and check at 375 px wide. Demo sign-in codes appear on screen.
- Say in the PR what you clicked through and at which widths.

## Style

- UI copy: short, plain, English. No emoji, no exclamation marks, no marketing filler.
- Visual: dark editorial (Instrument Serif headings, Inter text, ivory accent), Apple-minimal. Reuse the CSS variables in `:root` and existing classes before adding new ones; append new CSS in a labelled block at the end of `styles.css`.
- Keep functions small and close to where they're used. Comment the *why*, not the *what*.
